# Configuration

Every `SecurityConfig` field with its type, default, and effect. The
canonical field names are the snake_case python names (the cross-language
interop surface, spec 02): the Kotlin properties are the camelCase forms,
and adapters bind them idiomatically (Spring relaxed binding maps
`guard.redis-url` to `redisUrl`; Ktor takes the builder or the Kotlin
property names). Types and defaults are normative; a conformant build
with default config behaves as the reference with default config.

Generated by `docs/tools/w8d_config_docs.py` from
`ConfigFieldRegistry.kt` (the ported reference field table) joined with
the spec 02 field semantics. Re-run it whenever the registry or spec 02
changes; a field that exists in code but not here is a defect.

| `detection_max_json_depth` | `detectionMaxJsonDepth` | int, 1–1000 (ge=1, le=1000) | `32` | Max JSON nesting depth walked structurally. At the cap, the value is serialized to text and scanned as one value (still scanned, bounded by `detection_max_content_length`); one-time warning. |

| `detection_anomaly_threshold` | `detectionAnomalyThreshold` | float, 1.0–10.0 (ge=1.0, le=10.0) | `3.0` | Standard deviations from mean to flag an anomaly. |
| `detection_threat_score_threshold` | `detectionThreatScoreThreshold` | float, 0.0–10.0 (ge=0.0, le=10.0) | `1.0` | Anomaly score required to flag a request as a threat. |
| `detection_slow_pattern_threshold` | `detectionSlowPatternThreshold` | float, 0.01–1.0 (ge=0.01, le=1.0) | `0.1` | Execution time (seconds) to consider a pattern slow. |
| `detection_monitor_history_size` | `detectionMonitorHistorySize` | int, 100–10000 (ge=100, le=10000) | `1000` | Recent metrics kept in history. |
| `detection_max_tracked_patterns` | `detectionMaxTrackedPatterns` | int, 100–5000 (ge=100, le=5000) | `1000` | Max patterns tracked for performance. |
| `detection_anomaly_emission_cooldown` | `detectionAnomalyEmissionCooldown` | float, 1.0–3600.0 (ge=1.0, le=3600.0) | `60.0` | Min seconds between anomaly events for the same pattern. |
| `detection_min_samples_for_anomaly` | `detectionMinSamplesForAnomaly` | int, 10–1000 (ge=10, le=1000) | `30` | Samples recorded before anomaly detection engages. |
| `detection_compiler_timeout` | `detectionCompilerTimeout` | float, 0.1–10.0 (ge=0.1, le=10.0) | `2.0` | Timeout for pattern compilation and matching (seconds). |

## Registry fields beyond the spec 02 tables

These fields exist in the reference field table and the JVM
registry but have no row in the spec 02 field semantics tables.
Their effect text here is verified against the reference's field
descriptions (`guard_core/_security_config_fields.py`).

| Field | Kotlin property | Type | Default | Effect |
|---|---|---|---|---|
| `detection_binary_min_run_length` | `detectionBinaryMinRunLength` | int (ge=4, le=1024) | `16` | Minimum length a consecutive printable-character run inside a binary-dense multipart file-part payload must reach before that run is handed to the pattern scan. Text uploads and short or mostly-text payloads never reach the binary-density ratio and keep their full scan, and whole-body fallback scans are never island-reduced, so raw-body signature coverage stays intact. |
| `detection_pattern_validation_cache_path` | `detectionPatternValidationCachePath` | str or none | `None` | Optional file path for a disk-backed pattern-validation cache. When set, the empirical cost-verdict outcome of pattern-safety validation is cached keyed by pattern, flags, and engine version, so a process boot reuses prior certifications instead of re-timing every custom pattern; the cheap deterministic layers always re-run. Cache entries from a different engine version are ignored and overwritten. Leave unset (the default) to keep every validation fully empirical. |
| `exempt_ips` | `exemptIps` | str list (IP/CIDR) | `()` | IP addresses or CIDR ranges that skip rate limiting and the user-agent and cloud-provider checks.
