    W9b coverage report (engine + the fail-closed line gate)

    Measured 2026-10-12 with the W8d/W9a merged method: ALL module exec files counted against ALL kotlin classes (per-module reports UNDERCOUNT because the conformance module exercises facade/engine code from another JVM). Reproduce:

    ./gradlew test --no-daemon
MERGE_ONLY=1 scripts/enforce_line_coverage.sh /tmp/w9b

    Bugs found and fixed (byte-exact, with regression tests)

    1. Monitor anomaly cooldown compared raw nanoseconds against a seconds cooldown (Monitor.kt reserveAnomalyEmission): python times the window with time.monotonic() (seconds, monitor.py:197); the JVM fed System.nanoTime() straight in, making the suppression window 1e9x too small - every record re-emitted the anomaly to the agent sink. Fixed with the seconds analog. Regression: monitorAnomalyEmissionCooldownReservesPerPattern.
    2. positiveAssertion crashed on longer lookbehind witnesses (RepeatPrefixState.kt): python's state.text[: -len(witness.text)] yields "" when the witness exceeds the text (negative slice, _redos_repeat_prefix_state.py:101); the Kotlin substring threw StringIndexOutOfBoundsException. Fixed with the clamp. Anchored by the (?<=(X))\1 corpus shapes.
    3. Unterminated char classes crashed the structure scanners: python's reversed slices (pattern[i+1:j-1]) yield "" for a bare "[" (_redos_unreachable_terminator.py:77, _redos_structure_rules.py:58, _redos_structure_primitives.py); the Kotlin substring threw. Guarded at all five sites (UnreachableTerminator x2, StructureRules x2, StructurePrimitives x1).
    4. JsonMini coerced parsed JSON nulls to "" (ValidationCache.kt): python's json.loads preserves None and the load() shape checks reject a file with a null reason; the JVM accepted it as the empty string. A sentinel now preserves the null (cache-corruption contract).
    5. Atom-position 3-digit octal escapes parsed as group references (PyReParser.kt): "\\101" (octal 65 = 'A') became group reference 10 because the third-digit check peeked PAST the unconsumed digit (python's source.next is the char at the read position, sre_parse.py _escape). Fixed to peek().
    6. Overflowed brace-quantifier bounds silently became {0,0} (PyReParser.kt parseQuantifier): "x{99999999999}" must raise the repetition-number-too-large error (python MAXREPEAT check); the overflow flag only ran when parseDecimal returned null, but the overflow result carries parsed=false with a non-null Dec. Fixed.

    The fail-closed 100 percent line gate

    scripts/enforce_line_coverage.sh + scripts/enforce_line_coverage.py (the guard-core-rs enforce_line_coverage.py analog):

    1. Downloads jacococli 0.8.15-nodeps if absent, VERIFYING THE SHA256 (d2b74b20b415163c1f53261e7c5ef4445b788327094208ff821e0c2baf9bc8f1); a mismatch aborts the gate.
    2. Runs ./gradlew test (every module).
    3. Merges ALL exec files against ALL modules' kotlin classes via jacococli (the merged method is load-bearing: per-module reports undercount cross-JVM execution).
    4. enforce_line_coverage.py fails (exit 1) unless the workspace total AND every module hold 100.0 percent covered lines, printing the uncovered-line ranges per class, attributed per module, on failure. JaCoCo excludes in the build config are only acceptable for genuinely unreachable arms and must carry a written reason next to the exclude.

    Seeded-regression proof (run this wave): with ValidationCacheTest.kt removed, the engine test task stays green but the gate exits 1 and its report pins the exact uncovered lines:

    guard-core-engine: covered 6737, missed 670, 90.9545% (threshold 100.00%)
[guard-core-engine] com/guardcore/engine/detection/ValidationCache.kt
    lines: 45-46, 74, 87, 123-129, 131, 141-145, ...

    Restoring the test returns the engine to 91.68% (616 missed) and drops the class from the report. The gate catches a dropped/decayed test even when the test TASK stays green.

    ci.yml wiring (lands when the numbers hold)

    The gate is NOT wired into ci.yml in this wave: the workspace is at 90.76%, and a red gate on master is worse than a missing gate. The follow-up wave closes the remaining 2,160 lines (the facade worklist in docs/w9a-coverage.md, the conformance runner arms, and the engine tail below), then adds one job to ci.yml, byte-for-byte:

    coverage:
  name: coverage (100 percent line gate)
  runs-on: ubuntu-latest
  permissions:
    contents: read
  steps:
    - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      with:
        persist-credentials: false
    - uses: actions/setup-java@de727f081f381c8f8158605e0321c36c376e2e6 # v6.0.1
      with:
        distribution: temurin
        java-version: 17
    - name: Start Redis
      run: |
        docker run -d --name guard-redis -p 6379:6379 redis:8
        for i in $(seq 1 30); do
          if docker exec guard-redis redis-cli ping | grep -q PONG; then break; fi
          sleep 1
        done
    - name: Fail-closed 100 percent line-coverage gate
      run: scripts/enforce_line_coverage.sh
    - name: Stop Redis
      if: always()
      run: docker rm -f guard-redis || true

    plus coverage added to the required contexts and to the paths filter.
