    W3 handlers parity (guard-core-jvm)

    Wave 3 of the guard-core port: the remaining handler surface of the Python reference (guard_core/handlers/) into the guard-core facade module, with the handler test surface ported and green as the wave gate.

    Reference scope: guard_core/handlers/ is 10,353 LOC across 46 files (measured 2026-10-10, specs/impl/jvm.md module map). The _suspatterns_* family (4,414 LOC) landed engine-side in W2 and is out of W3 scope; the W3 handler scope is therefore ~5,875 reference LOC plus scripts/rate_lua.py (19 LOC) and the models slice DynamicRules/LastKnownRulesSnapshot (guard_core/_dynamic_rules.py, 124 LOC) that the dynamic-rule handler owns.

    Wave gate

    • Handler test surface ported to JUnit: 307 tests across 12 classes in guard-core/src/test/kotlin/com/guardcore/handlers/, all green.
    • Redis key schema byte-exact per spec section 08: unit-asserted against the pinned key strings/TTLs and proven by the vendored redis_interop corpus (14/14 cases, RedisInteropTest in guard-core-conformance, run against a live Redis under the suite prefix).
    • The live-Redis tests run under the conftest-identical isolation scheme (test:guard_core:<pid>:<hex>: prefix per run, HandlerTestSupport.kt).

    Observable identifiers (byte-exact)

    • Redis key schema (spec 08): {prefix}rate_limit:rate:{ip}[:{sha256(path)}] (zset, ttl window*2), {prefix}banned_ips:{ip} / {prefix}banned_networks:{cidr} (string ttl=duration), {prefix}behavior_usage:behavior:usage:{h}:{h} / {prefix}behavior_returns:behavior:return:{h}:{h}:{h} (zset, uuid4-hex members, ttl=window), {prefix}security_headers:{csp_config,hsts_config,custom_headers} (json, ttl 86400), {prefix}patterns:custom (comma-joined, persistent), {prefix}ipinfo:database (latin-1 blob, ttl=max_age), {prefix}cloud_ranges_v2:{provider} (sorted CSV, ttl), {prefix}cloud_ip_v2:{provider} (sorted-range JSON, persistent), {prefix}dynamic_rules:last_known (pydantic snapshot, persistent).
    • Event type strings: every handler event uses EventTypes constants (rate_limited, rate_limit_script_reloaded, redis_connection, redis_error, ip_banned, ip_unbanned, cloud_blocked, dynamic_rule_updated, dynamic_rule_applied, emergency_mode_activated, behavioral_violation, security_headers_applied, csp_violation, country_blocked, geo_lookup_failed, pattern_added, pattern_removed) with the python handler names (redis, rate_limit, ip_ban, cloud, dynamic_rules, behavior, security_headers, ipinfo, sus_patterns).
    • Header names/values: the security-headers default table, CORS response headers, and Retry-After are string-identical.
    • Check name rate_limit for the rate-limit log_activity path.
    • Rate-limit Lua script: byte-exact (RateLimitScript.kt), SCRIPT LOAD + NOSCRIPT reload recovery with the rate_limit_script_reloaded event.

    Idiom mappings

    • redis.asyncio.Redis -> Lettuce StatefulRedisConnection behind the RedisOperations interface; pipeline(transaction=True) -> MULTI/EXEC with per-command futures read in order. The redis-py client-level retry (Retry(ExponentialBackoff(), retries), redis_handler.py:116) maps to the Lettuce reconnect/timeout options: transient failures surface as GuardRedisError(503, ...) after the timeout budget either way.
    • cachetools.TTLCache -> handlers/TtlCache.kt (expiry-ordered eviction, lazy purge, injectable clock standing in for cachetools timer).
    • aiohttp.ClientSession -> JDK java.net.http.HttpClient (no redirects on the Azure download path, matching allow_redirects=False).
    • maxminddb.open_database -> com.maxmind.db:maxmind-db reader with a @MaxMindDbConstructor country record projection.
    • Mixins -> one class per python module group with internal/open members; _apply_blocking_rules and the application steps are open members so the python test idiom of overriding a step to drive the rollback path ports verbatim (ScriptedStepManager in the tests).
    • asyncio singletons (__new__-based) -> companion getInstance with resetInstance() test seams.
    • monkeypatch.setattr(manager, "ban_ip", fake) -> assertions against the real ban store (local TTL cache expiry) since Kotlin extension dispatch is static; durations pinned below the 3600s local cache cap to keep the same distinguishing power.
    • asyncio.create_task (ipinfo lookup-failure event) -> a manager-scope coroutine scope launch.

    Seams closed

    • G-2: ConfigSeams.geoIpHandlerFactory now constructs the real IpInfoManager (handlers/HandlerSeams.kt, registered from the facade entry point and the tests; python resolves the same construction lazily inside _security_config_geo_validators.py:69-94).
    • G-6: AccessControl.cloudIpChecker resolves through CloudManager's get_cloud_provider_details (handlers/HandlerSeams.kt).
