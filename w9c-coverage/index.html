    Bugs found and fixed (byte-exact, with regression tests)

    1. PyAst aug-assignment operators looped forever (PyAst.kt tokenize): the **= / //= / >>= / <<= arm ran i += 0, so any input containing those operators pinned the tokenizer (and the scan worker) in an infinite loop; python ast.parse raises SyntaxError immediately. Fixed with i += 3 (the token stream then fails the eval grammar, matching the python verdict). Regression: testAugmentedAssignmentOpsReject.
    2. The (?-i:...) scoped emitter inverted case sensitivity outside the scope (PyRe.kt emitScopedNodes): non-locked segments were wrapped using the BASE flags (the global flag minus the removed one), so under re.IGNORECASE the unlocked literal b in (?-i:a)b compiled case-SENSITIVE and the locked a case-INSENSITIVE - the exact opposite of python. Fixed by re-applying the ORIGINAL top flags to unlocked segments (and clearing them inside a delFlags scope), and by threading topFlags through assert/branch bodies. Regression: testScopedEmitterArms.
    3. The call-argument walrus never parsed its value (PyAst.kt parseCallArgs): f(x:=1) (valid python) was rejected because the := arm consumed the name and stopped. Fixed by parsing the assigned expression. Regression: testCallArgShapes.
    4. Valid python constructs the PyAst grammar rejected: f(*args, **kwargs) (the */** call-arg prefix order) and the interleaved comprehension clauses (for x in y if a for z in w if b) both raised against python-valid input; the comprehension loop was restructured into parseComprehensionClauses (if/for interleaving). Regressions in testCallArgShapes + testComprehensionContinuationAndTargets.
    5. \g<num> / \g<name> group references were rejected at parse time (PyReParser.kt parseEscapeAtom): python accepts the spelled-out form; the JVM raised "bad escape \g". Added the sre_parse-equivalent arm (numeric with the open/invalid-group guards, named via the group table). Regression: testCompileNamedGroupAndBackrefPattern.
    6. Dead defensive code removed (behavior-preserving): AmbiguousTail's shape-only parser (uncalled in python and the JVM), PyReParser's unreachable post-quantifier repeat check + the unreachable parseQuantifier fall-through + the sequence-level ')' atom arm, PyAst's atom-level lambda arm and the empty-call-arg arm (parseExpression always consumes or throws), PyRe's NOT_LITERAL/CATEGORY emitter arms (the parser never produces those node shapes), RegexWorkers' catch around FutureTask.run (failures ride the future), and the Manager's deadline catch around a Long.MAX_VALUE-bounded scan (byte-exact behavior; noted per site in the commit).
