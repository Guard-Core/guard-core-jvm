    Bugs found and fixed (byte-exact, with regression tests)

    1. global_behavior_rules setter used the wrong revalidator (SecurityConfig.kt): python coerces dict entries to BehaviorRuleConfig at assignment (_validate_typed_collection_field_value with _GLOBAL_BEHAVIOR_RULES_ADAPTER, pinned by test_global_behavior_rules_reassignment_coerces_dicts_to_model); the JVM setter ran the str-list validator and DROPPED/REJECTED the entries. Fixed with ConfigValidators.validateGlobalBehaviorRulesFieldValue.
    2. nowSeconds() resolution = the recurring rate-limit zwrite loss (IpBanBans.kt): System.currentTimeMillis()/1000.0 has millisecond resolution, so two sliding-window zadd calls inside the same millisecond produce the same sorted-set member and the second write is a silent no-op. python time.time() has microsecond resolution and never collides. The work order's "RateLimitManager pipeline+primitive interleave zwrite loss" flake (3 recurrences this wave) is this bug. Fixed with an Instant-based nowSeconds.
    3. redis_interop runner: score_equals_member compared RAW STRINGS (RedisInteropTest.kt): the reference harness (redis_interop_cases.py:311-313) pins the rate-limit zset contract as NUMERIC equality within 1e-6 (abs(score - float(member)) < 1e-6) because the member is rendered by the redis-side Lua, whose float formatting is build-dependent (the docker redis builds emit e-notation for sub-microsecond timestamps; glibc/macOS builds render positionally). The nowSeconds fidelity fix (item 2) is what surfaced it. The verifier now ports the numeric contract, and the CI redis images were aligned to the redis 8 major the corpus is generated against (matching the python family pin image: redis).
    4. Test-suite state leak (SusPatternsRegistryTest): removed a DEFAULT pattern from the process-global table and never restored it, disabling one detection pattern for every suite running after it.
