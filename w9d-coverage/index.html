    Bugs found and fixed (byte-exact, with regression tests)

    1. decodeSurrogateEscape rejected every F0-led 4-byte UTF-8 sequence (PenetrationDetection.kt): the b and 0x07 != 0 validity test fails for first byte 0xF0, i.e. ALL of U+10000..U+3FFFF (every emoji); python decodes them as the code point. Fixed with the CPython overlong/range guards (F0 -> second byte >= 0x90, F4 -> second byte <= 0x8F). Regression: testDecodeSurrogateEscapeMultibyte.
    2. decodeSurrogateEscape dropped bare continuation bytes: a standalone 0x80..0xBF byte decoded to nothing; python's surrogateescape maps each error byte to U+DC00+b. Added the length-1 decode arm. Same regression.
    3. decodeSurrogateEscape shifted the whole escape range by 0x80: the error-byte formula was 0xDC00 + b - 0x80 (0x80 -> U+DC00) instead of the PEP 383 mapping 0xDC00 + b (0x80 -> U+DC80); both error paths now carry the python-exact char, keeping the DetectionScanRedaction round trip intact. Same regression.
    4. Template keyword/expression indicators could never match: SusPatternsFileUploadTemplates searched with python endpos semantics over a java Matcher region, but java \Z is the ABSOLUTE end of input while python endpos TRUNCATES the subject (so \Z anchors at the barrier). The file-upload keyword scan was inert for every python-matchable frame. Fixed by truncating the subject to the barrier at both call sites. Regression: the template arms in EngineW9dTailsTest.
    5. Scoped (?L:...) leaked into the java pattern: the parser parsed the LOCALE letter then emitted the scope verbatim, so java died later with a bare "Unknown inline modifier" instead of the documented fail-closed UnsupportedPatternFeature (the top-level re.LOCALE gate's error). Fixed at the parser arm. Regression: the scoped-LOCALE arm in testPyReParserNumericGroupRefArms.

    Dead defensive code removed (behavior-preserving, written reasons inline): the DetectionEngineWiring DeadlineExceededException catch (Long.MAX_VALUE is the engine's no-deadline sentinel and never throws), the PairHiddenAssign escapedGapLength loop fall-through (the regex always matches exactly one named alternative), the LoggingUtils printable arm inside the surrogate-pair branch (a pair always decodes above the BMP), and the Monitor recent-times empty fallback (the window floor guarantees a non-empty deque after the append; python's conditional else is unreachable for the same reason).
